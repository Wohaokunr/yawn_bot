# 优化 WebUI 运行概览：展示真正有价值的监控数据

## 背景与问题

当前概览页（`webui/src/App.tsx` 的 `OverviewPage`，194-221 行）只有 4 个静态库存数字（Bot/群/用户/启用 Agent）、插件状态、"近期 Agent 操作" 5 条审计，以及一个**无意义的"运行指标"卡——只显示 Counter/Histogram 序列的个数，不显示指标内容**。而后端 `metrics.py` 里已经采集了 AI 调用量/延迟/降级等高价值数据，数据库里还有消息量、记忆治理健康、对局、任务队列等大量可用统计源，全部没有展示。

方案：后端在 `overview()` 中聚合出运营监控数据块 `stats`（带 15 秒 TTL 缓存防止 hub 5 秒轮询打爆 DB），前端重排概览页。**仅实时快照，不做趋势图**（用户已确认）。

## 后端改动

### 1. `src/plugins/yawn_core/metrics.py` — AI 健康汇总纯函数

新增 `summarize_ai_metrics(snapshot: dict) -> dict`，从 `snapshot_metrics()` 的结果派生：
- `requestsTotal` / `success` / `failed`（outcome != "success"，已知取值：error/timeout/empty/not_configured/cancelled/unsupported_multimodal）、`successRate`（0-1，无请求时 None）、`byOutcome` 列表（outcome + count）
- `avgDurationMs`（histogram sum/count）、`p95DurationMs`（累积 bucket：最小满足 cumulative/count >= 0.95 的上界；count=0 时 None）
- `degradations`（`yawnbot_ai_degradations_total` 求和）

### 2. `src/plugins/yawn_core/yawn_agent/memory.py` — 整理中群数

新增 `compacting_group_count()`：遍历 `_COMPACTION_LOCKS` 统计 locked 数（与现有 `is_memory_compacting` 同风格，加入 `__all__`）。

### 3. `src/plugins/yawn_core/webui/service.py` — `overview()` 增加 `stats` 块

- 模块级 `_LOADED_AT`（service 导入时刻 ≈ 插件加载）用于 `uptime.startedAt` / `uptimeSeconds`。
- 新增 `_load_stats()`：一个 session 内完成全部聚合，模块级 TTL 缓存（15 秒）+ `asyncio.Lock` 防并发重算。hub 每 5 秒轮询 `overview()`，缓存把 DB 压力降为每 15 秒一轮；bots/plugins/metrics 快照/generatedAt 仍每次现算。
- 聚合内容（新增返回体的 `stats` 键）：
  - `ai`：来自第 1 步的汇总（零 DB 成本）
  - `activity`：`messages24h`、`activeGroups24h`（GroupAgentMessage，`received_at >= now-24h`，有索引）；`agentResponseGroups24h`（GroupAgentConfig.last_response_at）；`proactiveToday`（SUM proactive_count WHERE proactive_day=今日）；`adminToolToday`（SUM admin_tool_count WHERE tool_day=今日）
  - `memory`：`compactingGroups`（第 2 步）、`rebuildRequired`、`failingGroups`（COUNT memory_rebuild_required / memory_consecutive_failures>0）、`recentError`（按 memory_last_attempt_at 最新且有 memory_last_error 的 groupId/error/at）
  - `games`：`live`（懒解析 `..yawn_rpg.state` / `..yawn_werewolf.state` 后 `all_games()` 计数；**不能 import webui/games.py——它 import service 会循环**，复制其 try/except 懒加载模式，子插件缺失时计 0 并标记 available）；`endedToday`（懒导入 RPGGame/WerewolfGame 模型 COUNT ended_at >= 今日 0 点）
  - `jobs`：`fanqie`（懒导入 FanqieJob，GROUP BY status 计数 queued/running/failed/completed）；`reminderErrors`（COUNT ScheduledReminder WHERE enabled AND last_error IS NOT NULL）
- 原有字段（bots/plugins/counts/recentAgentActions/metrics/generatedAt）全部保留，保证兼容；可选块（rpg/werewolf/fanqie）异常时优雅降级为 0/available:false，不影响整体。

## 前端改动（webui/src/）

### 4. `types.ts`

新增 `OverviewStats` 及子结构类型（ai/activity/memory/games/jobs/uptime），`Overview` 增加 `stats` 字段。

### 5. `App.tsx` — `OverviewPage` 重排

- **顶部 6 张 StatCard**（响应式 `xs=24 sm=12 lg=8 xl=4`）：在线 Bot、24h 消息量、24h 活跃群、AI 成功率（suffix 显示平均延迟）、进行中对局（RPG+狼人杀）、记忆异常群（>0 时红色警示样式）
- **"AI 服务健康"卡**：总调用/成功/失败/成功率/平均延迟/P95/降级次数 + 失败 outcome 的 Tag 分布（outcome 中文标签映射）
- **"记忆治理"卡**：整理中/待重建/连续失败群数、最近错误行（群号+错误+时间），带跳转 `/agent` 的链接
- **"活动与 Agent"卡**：今日主动消息、今日管理工具调用、24h 有回复的群、启用 Agent 群、已知用户
- **"游戏与任务"卡**：进行中/今日完局（RPG、狼人杀分列）、番茄 queued/running/failed、提醒异常数，跳转 `/games`、`/fanqie`
- **保留**"插件状态"与"近期 Agent 操作"卡；**删除**"运行指标（序列个数）"卡；Bot ID 列表并入插件状态卡或副标题
- PageHeader 副标题追加"已运行 X"（时长格式化）
- 提取纯 helper（`formatDuration`、outcome 中文标签映射、成功率显示）便于测试，风格与现有代码一致

## 测试

### 6. 后端 `tests/test_webui.py` / `tests/test_metrics.py`

- `summarize_ai_metrics` 数学正确性：total/success/failed/rate、p95 从累积 bucket 推导、空数据时 avg/p95/rate 为 None
- `_load_stats` DB 聚合：种入 GroupAgentMessage / GroupAgentConfig（含 proactive_day/proactive_count、memory_consecutive_failures、memory_last_error）/ ScheduledReminder 数据断言计数与 recentError 选取
- TTL 缓存：15 秒内命中缓存不重查、过期后刷新
- `overview()` 返回结构冒烟：包含 stats 各键、原有字段不变
- 子插件不可用降级：live games / fanqie 块计 0 不抛错

### 7. 前端 vitest

按现有纯函数测试模式（如 games.test.tsx），为新提取的 helper 写用例：时长格式化（秒→"x 小时 y 分"）、outcome 标签映射完整性、成功率百分比显示。
