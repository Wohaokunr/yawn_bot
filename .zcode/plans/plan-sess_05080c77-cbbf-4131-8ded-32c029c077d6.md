# 主动发言优化：修复完全失效 + 双模式"像真人"重构

## 问题诊断结论

**根因（完全不发言）**：`proactive.py:258` 把空 `tools=[]` 传给 `complete_with_tools`，而 `llm.py:271` 无条件把 `tools` 键透传给 API——OpenAI 兼容端点对空数组普遍返回 400，LLM 永远返回 None，主动发言每次抽中每次静默放弃（仅 warning 日志）。数据库审计显示 8 月 20 日成功 9 次后彻底停止，与端点行为变化吻合。

**不像真人的设计问题**：只在群冷场 ≥30 分钟才说话（+冷场分数 ≥0.6 双重门槛）；上下文只带 8 条消息、无记忆/成员/关系，max_tokens=160；prompt 无插话场景指引；bot 看不到自己说过什么。

## 变更清单

### 1. `src/plugins/yawn_core/llm.py` — 空 tools 根因修复
`complete_with_tools` 中 `tools` 为空列表时不传 `tools` 键（条件构造请求 kwargs）。

### 2. `data_models/group_agent_config.py` + 新迁移 — 3 个新配置字段
- `proactive_active_enabled: bool = True`（热闹插话开关）
- `proactive_active_probability: float = 0.08`（插话概率）
- `proactive_active_window_minutes: int = 8`（插话窗口分钟数）

新迁移 `data/nonebot_plugin_orm/migrations/yawn_core/<rev>_agent_proactive_active.py`，`down_revision="c3d8e5f17a92"`（当前 head），`batch_alter_table` 加 3 列（带 server_default 兼容存量行）。

### 3. `yawn_agent/context.py` — ActivitySnapshot 扩展
加 `last_member_message_at`（最近一条真人消息时间）和 `member_messages_60m`（60 分钟内真人消息数），为 bot 发言落库后区分"真人在聊"与"bot 自言"。

### 4. `yawn_agent/proactive.py` — 核心重构
**触发（`should_proactively_speak` 改为返回模式 "active"/"warmup"/None）**：
- 保留：enabled、trigger_mode、每日配额、bot 冷却（`is_cooldown_active`，防刷屏）
- **插话模式**：开关开启 + 最近真人消息距今在 [2min, window] 内（2 分钟最小间隔为内置常量防抢话）+ 60 分钟内真人消息 ≥3 条 → 掷骰 `proactive_active_probability`
- **暖场模式**：`idle >= idle_threshold_minutes`（沿用现有配置，idle 含 bot 消息）→ 掷骰 `proactive_probability`
- 删除 coldness≥0.6 硬门槛（与 idle 门槛重复设卡）

**生成（`_process_candidate`）**：
- 候选阶段（`_collect_candidates`）只产出 group_id/day_count/mode；真人消息统计按 `role != "bot"` 过滤
- 生成阶段在群锁内新开 session：重新读 config（复查 enabled/trigger_mode）→ 复用 `dialogue._load_context` 获得完整上下文（40 条消息+100 成员+30 记忆+50 关系，纯读函数可直接复用，无循环导入）
- 场景化 user_prompt 指引：插话="顺着最近话题自然插一句嘴，直接反应、1~2 句、像随手打字，禁止客套/开场白/总结"；暖场="冷场了随口说点什么活跃气氛，延续话题或抛轻松新话题，不要问'大家在吗'"
- LLM 参数：max_tokens 160→256、timeout 20→25s、tools=[]（修复后不再传该键）
- LLM 返回 None → warning 日志 + `_apply_result(text=None)` 推进 last_agent_at 做 20 分钟退避（止住每分钟重试风暴）
- 发送时取 `call_api` 返回的 `message_id`，成功后连同 bot 落库

### 5. `yawn_agent/dialogue.py` — bot 发言落库（自言记忆）
- `_send_group_text` 返回值 bool → `int | None`（message_id），`_send_unless_expired` 相应调整（None=失败/过期）
- 新 helper `persist_bot_reply(session, bot_id, group_id, message_id, text, retention_days)`：以 `role="bot"`、`user_id=bot_id` 插入 `GroupAgentMessage`（message_id 无效则跳过，避免违反 (bot_id, message_id) 唯一约束）
- 对话路径 `_finalize_reply` 与主动路径 `_apply_result` 发送成功后都调用 → bot 在上下文里能看到自己最近的发言，插话连贯、不重复
- `_load_context` 的 snapshot 构造补 `last_member_message_at`、`member_messages_60m`

### 6. WebUI 前后端
- `webui/service.py` `serialize_agent_config` + `webui/app.py` `AgentConfigPatch` 加 3 个字段（camelCase alias，概率 0-1、窗口 1-1440 校验）
- `webui/src/types.ts` + `webui/src/App.tsx` 表单加：插话开关（Switch）、插话概率（InputNumber）、插话窗口分钟（InputNumber）

### 7. 测试与验证
- `tests/test_agent_prompt_and_persona.py`：`should_proactively_speak` 双模式单测（fake config/snapshot + rng stub）：插话通过/窗口外/抢话间隔内/真人消息不足/冷却/配额/暖场通过/暖场阈值不足/插话开关关闭；llm 空 tools 不透传测试（monkeypatch fake client 断言请求 kwargs）
- `tests/test_webui.py`：补新字段校验
- 运行 pytest（相关文件）、ruff check/format（注意保持 LF 行尾）、webui vitest

## 默认行为效果（不动现有配置语义）
- 热闹群话题间隙 2~8 分钟时以 8%/分钟 概率插话 → 间隙内约 28% 触发，加 20 分钟冷却 ≈ 每 25~40 分钟一句，像话不多的真人群友
- 冷场 30 分钟后以 15%/分钟 概率暖场（现有行为，去掉双重门槛）
- 共用每日上限 12、冷却 20 分钟（被 @ 回复也计入冷却，真人也不会刚说完又主动说）

## 风险与对策
- bot 消息进入上下文改变对话路径 prompt → 模型能看到自己发言，行为改善；40 条窗口自然滚动
- 暖场 idle 含 bot 自己消息 → bot 说完 30 分钟没人接才会再暖场（更自然，接受）
- 迁移用 SQLite 安全的 batch_alter_table + server_default，存量行无感升级
