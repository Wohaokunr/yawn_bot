# 主动发言内容理解层优化（单次调用内嵌"理解-决策-生成"）

## 背景与目标

当前主动发言（`proactive.py`）的触发决策只看时间窗 + 消息计数 + 概率（`should_proactively_speak`），完全不读对话内容；触发后 LLM 收到的 prompt 只说"顺着话题插一句嘴"，没有拒绝权，产出容易是泛泛水话，且会在争吵/私密话题时硬插话。

目标：在一次 LLM 调用内完成"先读懂群聊 → 判断此刻该不该说话 → 该说才生成针对性发言"，不增加调用量；不适合时静默退避。用户已确认接受"发言频率略降、更挑时机"的取舍。

## 改动清单

### 1. `src/plugins/yawn_core/yawn_agent/memory.py` — 公开 JSON 解析函数
- `_parse_json_reply` 改名为公开的 `parse_json_reply`（容忍 code fence），模块内引用同步更新，加入 `__all__`。proactive 复用它，避免复制容错逻辑。

### 2. `src/plugins/yawn_core/yawn_agent/dialogue.py` — `_load_context` 支持消息时间标注
- 新增关键字参数 `include_message_age: bool = False`；为 True 时每条消息 dict 附加 `"minutes_ago": int((now - received_at).total_seconds() // 60)`，让模型分辨"3 分钟前在聊什么"与"一小时前的旧话"。
- 对话路径默认不传该参数，行为不变。

### 3. `src/plugins/yawn_core/yawn_agent/proactive.py` — 核心改动

**a) 重写两个 prompt 常量为结构化任务**（要求只返回 JSON `{"speak": 布尔, "topic": "话题简短概括", "reason": "一句话理由", "text": "消息，沉默时为空"}`）：
- `_ACTIVE_INTERJECT_PROMPT`（插话）：先理解话题/参与者/进展/气氛 → 判断是否适合插话，明确列出该沉默的情形（私密敏感话题、有人争论情绪激烈、话题刚收尾、最近多为图片表情包无可回应文字、没有针对具体内容的反应可说、与近期主动发言重复）→ 适合时对**某条具体消息或观点**做反应，1~2 句口语化，禁止"哈哈/确实"式泛泛附和。
- `_WARMUP_PROMPT`（暖场）：理解冷场前最后的话题 → 判断有无值得延续的话题或合适的新话题，没有就沉默 → 同 JSON 协议。

**b) 新增辅助 `_recent_proactive_lines(config)`**：从 `recent_response_fingerprints` 取 `input=="proactive"` 的最近 4 条文本，拼进 user prompt（"你最近主动说过：…不要重复相近说法"），用 prompt 层增强防撞重（fingerprint 全等比较保持不变）。

**c) 新增纯函数 `_decide_proactive_reply(raw: str)`**（返回 dataclass：should_speak / text / topic / reason）：
- JSON 解析成功：`speak` 为真且 text 非空 → 发言；否则 → skip（带 reason）。
- 解析失败但 raw 是非空纯文本（不以 `{` 或 ``` 开头）→ 按纯文本回退直接发言（兼容不吐 JSON 的模型，与旧行为一致）。
- 空文本或疑似畸形 JSON → skip。

**d) `_process_candidate` 改造**：
- `_load_context(..., include_message_age=True)`。
- LLM 调用从 `complete_with_tools(prompt, [], ...)` 换为 `complete(prompt, role="agent_dialogue", max_tokens=384, timeout=25)`；**不传 `response_format`**（避免个别对话模型端点不支持 json_object 直接 400，靠宽容解析 + 纯文本回退兜底）。
- skip 分支：`session.add(AgentAudit(tool_name="proactive_reply", result="skip", detail=reason))` 记录原因，再走现有 `_apply_result(text=None)` 推进 `last_agent_at` 防同话题反复抽卡，不发消息。
- 发言分支：fingerprint 撞重检查不变；发送成功且 topic 非空时写回 `config.active_topic = topic[:240]`（替代现在存触发消息原文的粗糙做法，让后续对话上下文拿到真实话题）。
- LLM 失败（返回 None）路径保持现状（warning + 退避）。

### 4. 测试 — `tests/test_agent_prompt_and_persona.py`
复用已有 `_load_agent_modules()` 全插件加载设施（已能导入 `should_proactively_speak`）追加单测：
- `_decide_proactive_reply`：合法 JSON speak=true / speak=false、code fence JSON、以 `{` 开头的畸形 JSON → skip、纯文本 → 回退发言、空文本 → skip。
- 新 prompt 常量包含 `speak`/`topic`/`text` JSON 协议关键词的冒烟断言。

## 明确不做
- 不改 `should_proactively_speak` 的时序/概率门（廉价门在前、内容门在后）。
- 不加 `GroupAgentConfig` 新列、无数据库迁移。
- 不改群锁协议与 `_apply_result` 既有语义。
