# yawn_agent 子插件优化计划（正确性修复 + 结构重构）

范围：`src/plugins/yawn_core/yawn_agent/`。不做性能优化、不动日志量、不改 ORM schema/迁移、不新增测试；验收标准为现有测试与静态检查全绿。

## 一、正确性修复（5 项）

**F1. 多图 caption 缓存污染（agent.py `_describe_images`，414-468 行）**
现状：多图一次 vision 请求生成单一 caption，却把同一 caption 写进每个 digest 的缓存（459-467 行）；后续任一单图命中缓存都会拿到混合描述。且 `prepare_image_inputs` 返回的 blocks 含 URL 透传图（无 digest），blocks 与 digests 并不对齐（可用 `image_url.url` 是否以 `data:` 开头区分）。
修复：重写为逐图独立转述——对每个有 digest 且未命中缓存的图单独调用 vision 模型，独立 `store_caption`；部分失败不影响已成功项。单图场景（最常见）行为不变；多图从 1 次调用变 N 次，但该路径本身就是多模态关闭时的降级路径，正确性优先。缓存命中短路（全部命中直接拼接返回）保留。

**F2. 统一 get-or-create config 并补竞态处理（commands.py `_get_config`，34-40 行）**
现状：与 `agent.py::_config` 重复实现，但缺少 IntegrityError 并发竞态处理（`block=False` 监听器下同群并发创建真实存在，agent.py 已处理过）。
修复：新建 `config_store.py`，把 agent.py 的实现移入为公开函数 `get_or_create_config(session, group_id)`；agent.py 与 commands.py 都改用它，删除两处重复。

**F3. commands.py 8 处裸 `session.commit()` 无异常兜底**
现状：全文件 8 处 commit、0 处 except；SQLite busy 时命令处理器直接向 NoneBot 抛异常。
修复：加辅助函数 `_commit(session) -> bool`（SQLAlchemyError 时 rollback + warning 日志，返回成败）；各命令失败时 `finish("操作失败，请稍后重试")`。

**F4. media.py 磁盘写失败仍插入无效缓存行（269-314 行）**
现状：OSError 时 `path = None` 后仍插入 `AgentMediaCache(cache_path=None, status="ready")` 行——该行无任何读取价值，还会让 `existing` 检查短路、阻止将来重试写盘。
修复：仅在磁盘写入成功时插入 DB 行；写失败则跳过插入并保留 dbg 日志。

**F5. proactive 发送与落库在群锁外（proactive.py `_process_candidate`，252-298 行）**
现状：群锁只包住 `complete_with_tools`，发送与 `_apply_result`（读-改-写 `recent_response_fingerprints`、`last_agent_at`）在锁外执行，与对话路径（锁内读-改-写同字段）存在丢更新竞态。
修复：把群锁范围扩大到"生成 → 撞重检查 → 发送 → `_apply_result`"全流程，与 `process_group_message` 的锁协议一致。

## 二、结构重构（agent.py 903 行 → 拆分）

**R1. 新建 `dialogue.py`，从 agent.py 移入对话主流程**
移入：`process_group_message`、`_describe_images`（F1 重写后）、`_is_recent_duplicate`。
agent.py 保留：监听器（`handle_group_agent_message`、`handle_member_notice`）、`should_respond`（测试从 agent.py 导入它，路径必须不变）、`_send_group_text`、`_deterministic_reply`、`_persist_message`。
`handle_group_agent_message` 的 `ensure_worker(..., process_group_message, ...)` 改为引用 `dialogue.process_group_message`。

**R2. `process_group_message`（约 315 行）拆子函数，目标顶层 ≤150 行**
- `_prepare_media_prompt(...)`：多模态关闭/缓存字幕时的 prompt 组装（现 516-539 行）
- `_finalize_reply(...)`：无工具调用分支的去重检查、发送、指纹记录、话题推进、commit 及失败回滚（现 642-707 行）
- 工具调用轮体保留在主循环内（状态耦合深，硬拆更难读），只把重复的"过期检查+发送收尾"收敛为小函数
行为逐行保持：dbg 日志、过期检查、MissingGreenlet 规避注释原样保留；新文件复制同款整行 `# ruff: noqa:` 头。

**R3. `__init__.py` 登记**：import 列表与 `__all__` 增加 `config_store`、`dialogue`。

## 三、明确不做
- 性能项（每消息深展开、工具能力探测 refresh、N+1 查询）——用户未选
- 日志精简；指纹与 proactive 撞重检查的合并（语义不同，前者防 LLM 重复输出，后者防与近期消息撞车）
- 不修改 `prepare_image_inputs` 返回签名（tests/test_agent_security.py 直接解包三元组）
