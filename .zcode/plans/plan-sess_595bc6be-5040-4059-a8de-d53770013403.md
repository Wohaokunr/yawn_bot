# 优化 yawn_agent 记忆系统并扩展 WebUI

已确认取舍：轻量相关性重排（不引入向量检索）、高频增量整理（不做对话内即时写入工具）、WebUI 四项功能全部纳入。

基于当前工作区（含未提交的 dialogue.py/memory.py/proactive.py 改动，在其上叠加、不回退、不主动提交）。

## 一、后端记忆系统优化（yawn_agent）

### 1. 相关性检索重排（核心）
`memory.py` 新增纯函数（进 `__all__`，便于单测）：
- `extract_bigrams(text) -> set[str]`：ASCII 词级 + 中文字符 bigram。
- `rank_memories(rows, recent_texts, speaker_id, now, *, limit=30)`：
  `score = salience * 0.5**(更新距今天数/21) * (0.6 + 0.4*confidence) + relevance + speaker加权(0.25)`
  relevance = 记忆 key(×2 权重)+content 与近 10 条消息 bigram 的归一化重叠。
- `dialogue.py::_load_context`：记忆查询 limit 30→120 候选，查完消息后调 `rank_memories` 取 30；speaker 取最后一条非 bot 消息的 user_id。签名不变（proactive 复用路径自动受益）。
- 关系边：优先保留 subject/object 出现在近 40 条消息 user_ids 中的边（按 confidence 排序），不足 15 条时回退全局 confidence 排序补足，上限仍 50。

### 2. 高频增量整理
- `compact_group_memory` 新增 `min_new_messages: int = 1` 参数：未整理消息数低于阈值时跳过 LLM 摘要，仅做过期清理。
- 同日摘要增量合并：existing 分支改为 `merge_daily_summary(old, new)`（拼接、保尾部 2000 字符，新增纯函数），salience 取 max，evidence_message_ids 合并去重取尾 50——修复一天多次整理互相覆盖的问题。
- `proactive.py::_restore_jobs`：保留 03:30 全量兜底 job（阈值 1），新增 `yawn_core_agent:compact_fast` 每 4 小时 job（阈值 60）。

### 3. 画像冲突处理
- 提炼纯函数 `merge_profile_update(old_content, old_conf, new_content, new_conf) -> (content, conf)`：新置信度≥旧则覆盖，否则保留旧内容。
- `_store_model_facts` 与 `_extract_structured_memories` 的更新分支改用它；相同内容仍走现有 evidence 合并逻辑。

### 4. 常量化
TTL 30/90/180 天与批量上限提为模块常量（`SUMMARY_TTL_DAYS` 等），不做 env 配置。

## 二、WebUI 后端新端点（webui/app.py，沿用现有模式）

写操作用 `WriteSession`（CSRF）+ `hub.notify_change`；乐观锁用 `check_version`；错误统一 HTTPException 中文消息。无 ORM 迁移（`memory_type` 为 String(24)，新增 "manual" 类型值不需迁移）。

1. `GET  /agent/groups/{gid}/memories/status` → {pendingMessages, lastCompactedMessageId, lastCompactedAt, countsByType, total, oldest/newestUpdatedAt}
2. `POST /agent/groups/{gid}/memories/compact` → 后台任务（app.py 内 `_spawn_background` + per-group in-flight set 防重复，独立 get_session，完成后 notify_change），立即返回 {started:true}；重复触发 409
3. `POST /agent/groups/{gid}/memories` → 手动新增（type∈{summary,profile,manual}、key、content、subjectUserId?、salience?、confidence?、expiresInDays?可空=永久）
4. `PUT  /agent/groups/{gid}/memories/{mid}` → 编辑 content/salience/confidence/expiresInDays（body.version 乐观锁），返回 serialize_memory
5. `GET  /agent/groups/{gid}/relations`（分页+search+type 筛选）、`DELETE /agent/groups/{gid}/relations/{rid}`
6. `GET  /agent/groups/{gid}/messages` → GroupAgentMessage 分页浏览（过滤已过期与隐私退出用户；serialize: id/userId/name/role/title/text/receivedAt）
7. `PATCH /agent/groups/{gid}/privacy/{uid}` {optedOut} → 退出=置 opted_out + `delete_member_memories`（与 /Agent隐私 命令同语义）；恢复=仅清标记。中间件自动审计。
- `service.py` 新增 `serialize_relation`、`serialize_agent_message`；status 查询逻辑放 service 或 app 内联小函数。

## 三、WebUI 前端

- 从 App.tsx 抽出 Agent 相关页面/面板到新文件 `webui/src/agent.tsx`（对齐 games.tsx/fanqie.tsx 一域一文件模式），App.tsx 仅留 import/Route/菜单。
- AgentDetailPage Tabs：运行配置 / 人设 / **记忆(升级)** / **关系边(新)** / **消息记录(新)** / **隐私退出(升级)** / 工具审计。
- MemoriesPanel：顶部统计卡（status 接口）+「立即整理」按钮（Popconfirm，触发后提示后台运行）+ 行内「编辑」Drawer（content/salience/confidence/expiresInDays，version 乐观锁、409 处理对齐现有写法）+「新增记忆」Drawer（manual 默认）。tab key 同步 useSearchParams 与现有一致。
- RelationsPanel：表格（主体/客体/类型/置信度/证据数/最后见到）+搜索+分页+单条删除。
- MessagesPanel：表格（时间/用户/昵称/角色/文本，展开看全文）+搜索+角色筛选+分页。
- PrivacyPanel：去掉只读限制，操作列加退出/恢复（退出 Popconfirm 强提示连带清除成员记忆）。
- `types.ts` 增加对应类型；`api.ts` 无需改；如需补充少量 `ag-*` 样式进 styles.css。

## 风险与注意
- `_load_context` 被 proactive 复用（include_message_age），重排内部完成、不改签名。
- 手动 compact 是重操作（LLM 摘要可达数十秒），必须后台执行并防并发重复；游标推进由 compact_group_memory 自身保证幂等。
- 隐私 PATCH 退出会清除成员数据（破坏性）：前端强确认、后端自动入 WebAdminAudit。
