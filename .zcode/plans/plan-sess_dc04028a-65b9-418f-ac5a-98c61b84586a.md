# 关系边系统优化方案

## 诊断结论（为什么"像个摆设"）

关系边目前只有写入端（异步整理的 LLM 提取 + `@提及`正则），消费端形同虚设：
- 注入格式无效：`dialogue.py:611-622` 把原始 JSON（user_id/confidence/evidence_count 数字堆）塞进易变层，静态规则对"关系"只字未提，模型无从利用；
- `relation_type` 自由发挥，同一关系拆成多条边互相挤占；
- 置信度只涨不跌（`memory.py:526-536`），老边霸占 top-20 注入名额；
- 对话时模型无任何查询/记录工具；WebUI 只能看和删；重建全量 wipe；`rank_relations` 是死代码。

按你确认的范围：提示词利用 + 提取质量与演化 + WebUI 管理 + 读/写工具 + 数据模型加 `source_kind`/`note`（一次迁移）。

## 1. 数据模型与迁移

**`src/plugins/yawn_core/data_models/agent_memory.py:68-94`** — `AgentRelation` 增列：
- `source_kind: Mapped[str] = mapped_column(String(16), default="auto", index=True)`，取值 `auto`（LLM 提取）/ `mention`（@正则）/ `agent`（对话工具）/ `manual`（WebUI 手工），对齐 `AgentMemory.source_kind` 模式；
- `note: Mapped[str] = mapped_column(String(200), default="")` — 一句话背景描述（如"常一起开黑"）。

**新迁移** `data/nonebot_plugin_orm/migrations/yawn_core/<新rev>_agent_relation_source_note.py`，`down_revision = "f8a1c2d3e4b5"`（当前链头）。仿照 `f8a1c2d3e4b5` 的两阶段模式：`batch_alter_table` 加列（带 `server_default`）→ 存量行回填 `source_kind='auto'`、`note=''` → 再移除 server default（默认值留在 ORM 层），并建 `ix_yawn_core_agentrelation_source_kind`。downgrade 反向删列。

## 2. 提取质量与演化（`memory.py`）

- 新增 `RELATION_TYPE_CHOICES`（好友/死党/情侣/伴侣/亲属/师徒/同事/同学/搭子/对立/常提及）与 `RELATION_TYPE_ALIASES`（朋友/好哥们→好友、对象/CP→情侣、仇人/死对头/宿敌→对立……），新增 `_normalize_relation_type(raw) -> str`（strip、别名映射、截断 32）。
- `_model_summary`（memory.py:263-278）system prompt：`relations` 项增加 `"note":"一句话背景"`，并要求 `type` 优先从枚举选择；`_RelationCandidate`（memory.py:76-83）加 `note: str = Field(default="", max_length=200)`。
- `_store_model_relations`（memory.py:477-536）：
  - 写入前对 type 做归一化；
  - 新边带 `source_kind="auto"`、note；
  - 已有边更新规则分来源：`manual`/`agent` 边只刷新 `last_seen_at`（不动 type/note/confidence，管理员与 Agent 的显式结论优先）；`auto`/`mention` 边维持现有置信度合并，note 仅在原值为空时补写；
- `_extract_structured_memories`（memory.py:1176-1199）：mention 边写 `source_kind="mention"`。
- `_rebuild_group_memories_locked`（memory.py:1101-1103）：删除条件加 `source_kind.not_in(("manual", "agent"))` —— 重建保留手工边与 Agent 对话中记录的边（后者无法从原文可靠再提取），与记忆的 manual 保护对齐。
- 新增导出函数 `effective_relation_confidence(confidence, last_seen_at, now)`：分段新鲜度权重（≤7天 ×1.0、≤30天 ×0.9、≤90天 ×0.7、≤180天 ×0.5），实现"老边退场、新边上位"，不改库内原始置信度（无写放大）。
- 删除死代码 `rank_relations`（memory.py:203-225、`__all__` 及其两个测试）。

## 3. 提示词利用（`dialogue.py` / `prompt.py` / `context.py`）

- `_load_context`（dialogue.py:584-623）：SQL 候选池扩到 60 条（仍限当前参与者、排除隐私退出），Python 内按 `effective_relation_confidence` 重排取前 20，渲染为**可读文本行**列表，如 `"小张(123) —情侣→ 小李(456)：最近官宣过"`（note 为空则省略冒号段）；名字解析失败兜底为 QQ 号字符串（当前渲染成 `null`）。仍留在易变层，不影响前缀缓存设计。
- `prompt.py` `_STATIC_RULES`（prompt.py:13-18）追加一句："relations 列出成员间已知关系，用于称呼与回应分寸的参考；未列出的关系不得臆造。" `PROMPT_VERSION` 升到 `yawn-agent-v5`。
- `context.py:88-95`：`stable_relations` 局部变量改名（它在易变层，现名误导），并加注释说明。

## 4. 对话时工具（`tools.py`）

在 `build_tool_schemas`（tools.py:47-214）基础 definitions 中注册两个无 OneBot 能力依赖的工具：
- `list_user_relations(user_id: int)`：返回该成员双向全部边（type/note/有效置信度/最后见到），过滤隐私退出端点，上限 30 条——补足 top-20 之外的可见性；
- `record_user_relation(subject_user_id: int, object_user_id: int, type: str, note: str = "")`：校验双方均为本群真实成员（`UserGroup`）、subject≠object、端点未隐私退出、type 归一化后非空；已有 `manual` 边拒绝改动（提示"由管理员维护"），其余已有边刷新 last_seen/evidence 并按规则补 note，新边 `source_kind="agent"`、`confidence=0.6`；执行后走既有 `_audit` 审计。持久化依赖对话工具轮后的既有 `session.commit()`（dialogue.py:1084-1091），无需新提交路径。
- `_check_tool_policy`（tools.py:268-324）无需改动（两者非 admin 工具、不要求 OneBot action）；`session is None` 时在分支内直接返回错误。

## 5. WebUI 管理（`webui/app.py` / `service.py` / `agent.tsx` / `types.ts`）

- `serialize_relation`（service.py:476-486）加 `note`、`sourceKind`；`types.ts:111` 的 `AgentRelationItem` 同步。
- `POST /agent/groups/{group_id}/relations`：创建 manual 边（主体/客体 QQ、类型、备注、置信度默认 0.9），校验 subject≠object、type 归一非空、端点未隐私退出，uq 冲突返回 409，成功后 `hub.notify_change("agent_relation", ...)`。
- `PUT /agent/groups/{group_id}/relations/{relation_id}`：仅允许改 `note` 与 `confidence`（type/两端固定，避免 uq 冲突；改类型走删除+新建）。
- `GET /agent/groups/{group_id}/relations/types`：distinct 类型列表，供筛选下拉。
- 导出端点（app.py:602-641）payload 增加 `"relations": [...]`（应用同样的隐私过滤）。
- `agent.tsx` `RelationsPanel`（261-272 行）：加"新增关系边"按钮 + Drawer 表单（类型下拉支持自由输入）、类型筛选 Select、来源 Tag（手工/自动/提及/Agent）、备注列、"编辑"（note+confidence）操作；风格对齐 MemoryPanel 现有 Drawer 模式。

## 6. 测试与验证

- `tests/test_agent_memory.py`：删 `rank_relations` 两测；新增类型归一化、note 提取与补写、manual/agent 边重建保护、mention 边 source_kind、`effective_relation_confidence` 分段、compaction 集成断言新列。
- `tests/test_agent_prompt_and_persona.py`：更新易变层断言为文本行格式；确认版本号无硬编码依赖。
- `tests/test_webui.py`：POST/PUT/types/导出 relations 的接口测试（含 409 冲突与隐私过滤）。
- 运行：`pytest tests/test_agent_memory.py tests/test_agent_prompt_and_persona.py tests/test_webui.py`，加 Ruff、Pyright；前端跑既有 vitest 与 `tsc` 构建确认类型无误。

## 实施顺序

迁移+模型 → memory.py（归一/演化/重建保护/清理死代码）→ prompt/dialogue 注入 → tools 读写工具 → WebUI 后端 → WebUI 前端 → 测试补齐与全量检查。
